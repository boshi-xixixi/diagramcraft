# 输入语法参考（9 种图）

所有格式都是「纯文本 + 空格缩进」，没有 Tab，没有 Markdown 代码块。
生成后的文本可以直接粘到渲染器左侧输入框，或通过 `?type=&text=` 深链传入。

---

## 1. module · 功能模块图

规则：
- 第 1 行顶格写系统名称（根节点）。
- 第 2 级缩进 2 个空格，第 3 级 4 个空格，第 4 级 6 个空格，最多 4 级。
- 每级子项 3~6 个，最后一级写具体功能点。
- 不写序号、不用 `-`/`*`/`·`。

示例：

```text
学生信息管理系统
  学生端
    个人信息查看
    课程查询
    成绩查询
  教师端
    学生信息查询
    成绩管理
  管理端
    学生信息管理
    课程管理
```

---

## 2. flow · 流程图

规则：
- 每行 `序号-类型-文本`，序号从 1 连续编号。
- 类型只能是：`开始` `结束` `处理` `判断` `输入` `输出` `异常`（无法识别时按「处理」画）。
- 判断分支写在判断节点下一行，缩进 2 个空格：`是-目标序号` / `否-目标序号`，可多条。
- 跳转：文本末尾加 `->序号`，例如 `7-处理-返回重填->2`。

示例：

```text
1-开始-开始登录
2-输入-输入账号和密码
3-处理-提交登录请求
4-判断-账号密码是否正确？
  是-5
  否-2
5-处理-登录成功
6-结束-流程结束
```

形状约定：开始/结束=圆角矩形，输入/输出=平行四边形，判断=菱形，异常=虚线框，处理=矩形。

## 3. usecase · 用例图

规则：
- 顶格写角色：`角色：学生`（也可直接顶格写角色名）。
- 角色下的用例缩进 2 个空格。
- 被包含的用例：用例名前加 `<i>`，再缩进 2 个空格，挂在上一行用例下。
- 扩展用例：用例名前加 `<e>`，同样再缩进 2 个空格。
- 2~4 个角色，每角色 3~6 个用例。

示例：

```text
角色：学生
  选课
    <i>校验学分
  查询成绩
角色：教师
  录入成绩
  成绩统计
```

---

## 4. architecture · 系统架构图

规则：
- 顶格=层级名（如 用户层、应用层、数据层、横切关注点）。
- 缩进 2 空格=该层模块。
- 缩进 4 空格=模块说明（可选，多条用 ` / ` 分隔）。
- 名称含「横切」或「公共」的层画成虚线区域。

示例：

```text
用户层
  学生端
    选课 / 成绩查询
  教师端
    成绩录入 / 课程管理
应用层
  业务服务
    选课服务 / 成绩服务
数据层
  数据库
    MySQL / Redis
横切关注点
  认证 / 日志 / 监控
```

---

## 5. sequence · 时序图

规则：
- 首行可写 `标题：登录时序图`。
- 参与者先列出来：`参与者：前端页面`，或直接写名字；`角色 用户` 会画成小人。
- 消息：`发送方 -> 接收方：消息内容`。
- 返回：`接收方 --> 发送方：返回内容`（虚线箭头）。
- 名字前后必须一致；消息按时间顺序从上到下。

示例：

```text
标题：登录时序图
角色 用户
参与者：前端页面
参与者：授权服务
参与者：数据库
用户 -> 前端页面：输入账号密码
前端页面 -> 授权服务：提交登录请求
授权服务 -> 数据库：校验用户信息
数据库 --> 授权服务：返回用户数据
授权服务 --> 前端页面：返回登录令牌
前端页面 --> 用户：登录成功
```

## 6. uml · UML 类图

规则：
- `类 学生` / `抽象类 教师` / `接口 可登录` / `枚举 选课状态`。
- 类下用 `属性:` 与 `方法:` 两节，成员缩进 2 个空格。
- 属性：`+学号: string`；方法：`+登录(账号: string, 密码: string): bool`；`+` public、`-` private。
- 关系写在最后，`关系:` 开头，格式 `A "1" -- "*" B : 标签`。
- 符号：`--` 关联、`-->` 有向关联、`..>` 依赖、`--|>` 继承、`..|>` 实现、`--o` 聚合、`--*` 组合。
- 多重度写在引号里：`"1"`、`"0..1"`、`"*"`。

示例：

```text
类 学生
属性:
  +学号: string
  +姓名: string
方法:
  +登录(账号: string, 密码: string): bool

类 课程
属性:
  +课程ID: int
  +课程名: string

关系:
学生 "1" -- "*" 课程 : 选修
```

## 7. er · ER 属性图（Chen 记法）

输入 MySQL 建表语句或 DBML；矩形=实体，椭圆=属性（主键加下划线），菱形=联系。

示例：

```sql
CREATE TABLE `sys_user` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '用户ID',
  `username` VARCHAR(50) NOT NULL COMMENT '用户名',
  `role_id` BIGINT NOT NULL COMMENT '角色ID',
  PRIMARY KEY (`id`),
  CONSTRAINT `fk_user_role` FOREIGN KEY (`role_id`) REFERENCES `sys_role` (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';

CREATE TABLE `sys_role` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '角色ID',
  `role_name` VARCHAR(50) NOT NULL COMMENT '角色名称',
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='角色表';
```

DBML 写法也支持：`Table 表名 { 字段 类型 [pk] }` + `Ref: 表.字段 > 表.字段`。

---

## 8. globalEr · 全局 ER 图

输入同上。差别：每张表画成一个实体框，字段直接列在框内，外键用菱形连线并标注 1 / N，适合放进论文「数据库设计」一节。

---

## 9. table · 数据库三线表

输入同上。每张表输出一张三线表，列固定为：
`字段名 | 数据类型 | 字段长度 | 主键 | 是否为空 | 默认值 | 字段说明`

字段的中文说明取自 `COMMENT`；主键列显示 Y/N。适合直接截图放进论文。

---

## 通用注意

- 缩进只用空格；解析器对 Tab 会做 2 空格替换，但仍建议用空格。
- 所有名称尽量短；太长会导致节点过宽。
- 一次只放一种图的内容，不要把两种图混在一个输入框里。
